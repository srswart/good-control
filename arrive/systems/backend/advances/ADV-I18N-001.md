### Key Features Implemented

1. **Locale Support**
   - `SupportedLocale` enum with English and Chinese (Simplified)
   - Locale detection from strings (e.g., "en", "en-US", "zh", "zh-CN")
   - Default locale (English) with fallback behavior
   - Native language names ("English", "中文")

2. **Translation System**
   - Fluent-based translation engine
   - Message formatting with variable interpolation
   - Fallback to default locale when translation missing
   - Builder pattern for configuring translator

3. **Error Handling**
   - Comprehensive error types for i18n operations
   - Clear error messages for unsupported locales and missing translations

4. **Locale Context**
   - `Locale` struct for request/session context
   - Language identifier integration with unic-langid
   - Automatic locale detection from Accept-Language headers

### Test Coverage

- **11 unit tests** covering:
  - Supported locale enumeration and properties
  - Locale code and native name retrieval
  - Locale parsing from various formats (en, en-US, zh, zh-CN)
  - Locale detection with fallback
  - Simple translation (EN and ZH)
  - Translation with variable arguments
  - Fallback to default locale
  - Missing translation error handling

### Integration Points

- **Foundation for bilingual features:**
  - Master data fields (item names, descriptions) can use `SupportedLocale`
  - Document pack language selection can use `Locale::detect()`
  - API responses can include translations via `Translator`

- **Future enhancements:**
  - Load translations from files (FTL format)
  - Database-backed translations for dynamic content
  - Locale-specific formatting (dates, numbers, currency)
